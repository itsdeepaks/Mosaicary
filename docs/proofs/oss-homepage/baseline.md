# Online Scope Studio Homepage — Baseline Measurement Plan

Status: **Slice 5.1 baseline**  
Observed page: `https://www.onlinescope.in/`  
Observation date: 2026-08-04

## Purpose

The proof must compare a Tessli-assisted workflow with the current manual workflow without backfilling convenient numbers after the result is known.

## Current manual workflow

Before this proof, OSS homepage design research generally involved:

1. browsing a large manually curated design-resource list;
2. opening references individually;
3. collecting screenshots, URLs, section ideas, and implementation references in separate places;
4. explaining selected examples to Figma or Codex;
5. rebuilding sections when generated UI felt generic or inconsistent;
6. relying on conversational memory and ad-hoc Markdown notes across sessions.

This is owner-reported process context, not a timed benchmark.

## Baseline observations

- The current title is centred on website development for small businesses in India.
- The current hero combines websites and systems in one broad statement.
- The page contains audience, expertise, process, selected-work, tools, automation, and CTA sections.
- Service presentation is platform/deliverable heavy.
- Real project names are present, but this baseline does not independently verify outcome claims.

## Measurement rules

- Do not convert `not measured` into zero.
- Preserve the first candidate before fixes.
- Record browser findings before changing the candidate.
- Human scores must come from an actual reviewer and include notes.
- Failed or neutral results remain valid evidence.
- One candidate cannot establish a general UI-taste claim.
