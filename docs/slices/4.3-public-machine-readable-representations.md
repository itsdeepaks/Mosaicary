# Product Plan v2 — Phase 4 / Slice 4.3

Status: **IN PROGRESS**

## Goal

Publish deterministic, bounded, repository-backed Markdown and JSON representations for one source or one published collection at a time, without exposing browser-local Boards or creating a bulk catalogue dump.

## Public routes

```text
/resources/[slug]/profile.json
/resources/[slug]/profile.md
/collections/[slug]/collection.json
/collections/[slug]/collection.md
```

## Acceptance criteria

- every canonical source slug exposes deterministic JSON and Markdown;
- every published collection slug exposes deterministic JSON and Markdown;
- source representations consume the canonical SourceProfile adapter;
- collection representations preserve repository editorial order;
- Listed/Profiled/Verified state remains truthful;
- repository intelligence is explicitly distinguished from live-provider verification;
- JSON has stable property order, UTF-8, two-space indentation, LF endings, and one final newline;
- Markdown has fixed section order, LF endings, no trailing whitespace, and one final newline;
- no route exposes Board IDs, Board text, Saved state, account data, cookies, credentials, environment values, or provider-fetched content;
- there is no all-295 JSON or Markdown endpoint in this slice;
- responses use correct content types, `nosniff`, public CORS, cross-origin resource policy, cache headers, canonical/alternate Link headers, and indexable robot headers;
- routes are statically enumerable and unknown slugs/formats fail safely;
- source and collection HTML routes remain canonical;
- the sitemap includes the four representation families;
- focused formatter, privacy, route, deterministic-output, and browser/release checks pass;
- Phase 4 completes and Phase 5 / Slice 5.1 becomes NEXT only after exact-head validation.

## Exclusions

- no public Board route or exported Board persistence;
- no bulk catalogue endpoint;
- no search API, semantic/vector endpoint, GraphQL API, or new MCP tool;
- no provider fetch, screenshot, live verification, or pricing refresh;
- no auth, cloud sync, sharing, analytics, forms, moderation, or email;
- no catalogue/profile/evidence mutation;
- no homepage, navigation, playbook, Pattern Candidate, or OSS proof implementation;
- no dependency, Supabase, credential, or deployment-state change.

## Expected files

- `web/lib/public-representations.mjs`;
- `web/lib/public-representations.d.mts`;
- source and collection representation Route Handlers;
- focused tests;
- sitemap and release-browser coverage;
- Product Plan v2 ledger/evidence updates.

## Security and privacy boundary

All output is derived from committed public repository data. The implementation must not read local storage, cookies, sessions, request bodies, user input, Board state, Saved state, environment secrets, remote providers, or private content while generating representations.

## Rollback

Remove the representation module, route handlers, tests, sitemap entries, and ledger updates. Existing HTML routes, Board export, catalogue, MCP, and local data remain independently valid.
