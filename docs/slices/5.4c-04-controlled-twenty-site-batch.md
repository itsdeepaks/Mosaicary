# Slice 5.4c-04 — controlled twenty-site screenshot batch

Status: **implementation and evidence collection in progress**

## Goal

Measure the verified screenshot pipeline on a deliberately mixed twenty-site
batch before any larger catalogue run or production-media publication.

This is not the first twenty pending records and not an easy-only sample. The
fixed composition is:

- **12 unseen resources** that have never received browser screenshot review;
- **3 suitable controls** that should remain clean;
- **3 protected-page controls** that must remain terminal blocked results;
- **2 strict consent edge cases** that require the reviewed Pixelbuddha and
  Relume strategies.

### Strict consent edge cases

- Pixelbuddha;
- Relume.

## Capture contract

- one pull-request workflow trigger for the immutable batch;
- batch ID: `controlled-20-v1-20260803`;
- browser viewport: **1440 × 756**;
- output: **960 × 504 WebP**;
- maximum image size: **307,200 bytes**;
- fresh accessibility snapshot and overlay audit after every interaction;
- exact reviewed non-consenting actions only;
- terminal blocked states remain visible and are never bypassed;
- raw images, optimized images, manifests, logs, and contact sheet retained in a
  review artifact;
- no Supabase upload and no production media change.

## Safety boundary

No Accept, Agree, Allow all, general consent-save, CAPTCHA bypass, login bypass,
paywall bypass, protected-page bypass, DOM deletion, CSS hiding, or screenshot
editing is permitted.

Pixelbuddha's state-dependent `Deny` action remains guarded behind proof that
Necessary is checked and disabled and all reviewed optional switches are off.

## Acceptance criteria

- [ ] exactly twenty unique fixed resources produce terminal records;
- [ ] all twelve unseen resources are represented;
- [ ] all three suitable controls remain visually suitable;
- [ ] all three protected-page controls remain blocked rather than bypassed;
- [ ] Pixelbuddha and Relume retain verified clean state;
- [ ] every successful output is 960 × 504 WebP below 307,200 bytes;
- [ ] contact-sheet review independently classifies every capture;
- [ ] no production media record or Storage object is changed;
- [ ] temporary workflow is removed after evidence collection;
- [ ] final cleaned diff passes normal repository checks.

## Decision gate

The result will decide whether to proceed with another controlled batch, improve
specific interaction classes, or stop screenshot automation for remaining
sources. It cannot directly authorize production publication or an unattended
all-catalogue run.
