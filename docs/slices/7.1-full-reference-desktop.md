# Slice 7.1 — Full Reference desktop table and list

Status: **in progress**

## Goal

Replace the Full Reference placeholder with a dense, research-oriented desktop catalogue that exposes all 295 validated resources through URL-restorable search, category, access, and sort controls without prematurely implementing the tablet/mobile filter sheet and compact rows reserved for Slice 7.2.

## Acceptance criteria

- `/resources` renders a complete desktop Full Reference from `web/data/catalogue.json`;
- the desktop view uses a compact title area, real statistics, a left filter sidebar, a central semantic resource table/list, and a right factual supporting panel;
- all 295 validated resources are visible and reachable on the unfiltered desktop view without pagination, load more, or virtualization;
- search matches the same normalized catalogue fields used by Explore;
- category is an exact filter, selected access models use OR semantics, and curated/A–Z/Z–A sorting remains deterministic;
- `q`, `category`, `access`, and `sort` serialize to canonical shared URLs;
- search commits with `replaceState`; category, access, sort, and reset use `pushState` while preserving existing Next.js history state;
- browser back and forward restore search, selected filters, sort, and the matching table rows;
- result counts are visible and announced;
- rows display factual resource name, domain, description, category, access model, and a native secure external link;
- no row exposes save controls before browser persistence exists;
- the supporting panel includes only real catalogue facts and contribution/curation links;
- popular/trending tags are omitted because the catalogue has no validated popularity or tag-frequency signal;
- empty and defensive data-error states are designed without exposing raw errors;
- below the desktop breakpoint, the dense desktop interface is withheld and an honest Explore handoff preserves the current discovery parameters;
- no filter dialog, tablet sidebar collapse interaction, or compact mobile resource row is implemented in this slice;
- desktop and smaller-screen handoff layouts pass at 1440, 1024, 768, 390, and 320px without horizontal overflow;
- semantic table/list structure, labels, keyboard focus, native controls, and forced-colours behaviour pass;
- formatting, types, lint, Node tests, catalogue drift, production build, route smoke, browser interactions, and responsive screenshots pass;
- `build-slices.md` records `7.1 DONE / 7.2 NEXT` only after final verification.

## Expected files

- `web/components/full-reference/*`;
- replacement `web/app/resources/page.tsx`;
- focused source and browser tests;
- updated `web/tests/footer-route-integrity.test.mjs`;
- `.github/workflows/web-ci.yml` route, browser, and screenshot coverage;
- `build-slices.md` after final verification.

## Exclusions

- no tablet/mobile filter sheet;
- no compact mobile resource rows or progressive metadata controls;
- no save action or browser storage;
- no resource detail route;
- no collection, catalogue, schema, or source-data changes;
- no preview/favicon scraping, remote metadata, or external media requests;
- no popular/trending tags or invented curation signals;
- no pagination, load more, virtualization, or infinite scroll;
- no authentication, Supabase, or cloud data;
- no dependency or lockfile change;
- no production cutover.

## Responsive decision

The dense three-column Full Reference is a desktop surface in Slice 7.1. Smaller screens receive a truthful, accessible handoff to Explore that preserves the same discovery parameters. Slice 7.2 will replace that handoff with a real tablet/mobile filter sheet and compact resource rows.
