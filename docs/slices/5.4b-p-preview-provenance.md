# Slice 5.4b-p — Open Graph and Twitter preview provenance

Status: **contract committed — helper matcher correction in progress**

## Goal

Correct the metadata-discovery contract before Batch 6 so Tessli can preserve
whether a reviewed preview came from Open Graph or Twitter metadata instead of
labelling every preview generically as Open Graph.

## Repository finding

The current parser checks `og:image:secure_url`, `og:image`, `twitter:image`, and
`twitter:image:src`, but returns a plain URL list. The discovery result then
writes `source: "open-graph"` for the first successful URL even when that URL
came only from Twitter metadata. Both media schemas currently accept only
`manual` and `open-graph`, so exact Twitter provenance cannot be recorded.

Starting another reviewed batch with that behavior would create false evidence
and violate the requirement to report each candidate's actual metadata source.

## Acceptance criteria

- metadata extraction preserves each candidate URL together with the exact
  declaring property in priority order:
  `og:image:secure_url`, `og:image`, `twitter:image`, then
  `twitter:image:src`;
- discovery continues trying candidates in that order and records the exact
  successful metadata property;
- preview `source` distinguishes `open-graph` from `twitter` for new discovery;
- candidate and approved-media schemas accept `twitter` previews and an optional
  exact `sourceProperty` field;
- source-property validation rejects mismatches such as `source: "twitter"`
  paired with `og:image`, or `source: "open-graph"` paired with
  `twitter:image`;
- legacy approved records without `sourceProperty` remain valid because their
  exact declaring property was not recorded historically and must not be
  invented retroactively;
- new discovery results always include `sourceProperty` for Open Graph and
  Twitter previews;
- manual previews cannot claim an Open Graph or Twitter source property;
- deterministic review reporting and catalogue composition remain compatible;
- focused tests cover Open Graph priority, Twitter fallback, duplicate URL
  declarations, relative URL resolution, rejected first candidates, and schema
  mismatch cases;
- normal build/test/CI remains network-free and no approved production record,
  coverage disposition, generated catalogue, or public UI changes in this
  slice;
- format, typecheck, lint, all tests, media review/coverage/catalogue checks,
  production build, and repository workflows pass;
- complete diff contains no external binary, screenshot, candidate discovery
  output, secret, dependency, unrelated media approval, auth, Supabase, or UI
  change;
- this slice is squash-merged before the real 5.4b-06 resource batch begins.
