# Slice 6.2 — Collections page and collection detail

Status: **in progress**

## Goal

Replace the Collections placeholder with a truthful, responsive index of the six repository-maintained launch collections and static detail routes that expose each collection's ordered resources.

## Acceptance criteria

- `/collections` renders all six published repository collections from `web/data/catalogue.json`;
- collection order follows the reviewed source order;
- collection cards support featured and compact visual variants without implying popularity or trend;
- every collection card includes a CSS-generated cover composition, title, factual description, item count, and real last-reviewed date;
- no collection card exposes a save action before collection persistence exists;
- no curator, avatar, popularity, trend, activity, or save count is invented;
- every collection card is a native internal link to `/collections/[slug]`;
- all six detail routes are statically generated from published collection slugs;
- unknown collection slugs use the application 404 path;
- collection detail includes title, purpose, item count, description, real last-reviewed date, correction/contribution link, and all ten ordered resource cards;
- detail resource cards remain native external links and omit non-persistent save controls;
- collection/resource ID relationships are resolved from the validated application catalogue, with missing references treated as data errors rather than silently discarded;
- the Collections navigation item remains active on collection detail routes;
- layouts pass at 1440, 1024, 768, 390, and 320px without horizontal overflow;
- keyboard, focus, semantic heading/list, and forced-colours behaviour pass;
- route smoke, formatting, types, lint, Node tests, catalogue drift, production build, browser interactions, and responsive screenshots pass;
- `build-slices.md` records `6.2 DONE / 7.1 NEXT` only after final verification.

## Intentional page-contract decisions

- no collection search at launch because six visible collections do not justify a search control;
- no collection-category navigation because collection categories are not defined in repository data;
- no Recent or Trending section because there is no usage or publication-history signal beyond the real review date;
- visual featured/compact variants express layout hierarchy only and are not labelled as popularity.

## Expected files

- `web/lib/collections.ts`;
- `web/components/collection-card/*`;
- `web/app/collections/page.tsx` and styles;
- `web/app/collections/[slug]/page.tsx` and styles;
- focused source and browser tests;
- `.github/workflows/web-ci.yml` route and screenshot coverage;
- `build-slices.md` after final verification.

## Exclusions

- no collection search, filters, category navigation, sorting, pagination, or load more;
- no save collection action or browser storage;
- no user-created/private collections;
- no authentication, Supabase, or cloud data;
- no collection editor or moderation workflow;
- no collection-source/schema/member changes;
- no resource metadata enrichment or remote media;
- no resource detail route;
- no dependency or lockfile change;
- no production cutover.
