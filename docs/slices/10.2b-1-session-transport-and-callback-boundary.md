# Slice 10.2b-1 — Session transport and safe callback boundary

## Goal

Add the server-side cookie transport and callback boundary needed by a future
Tessli authentication slice without enabling a sign-in provider, changing
Supabase Auth settings, or sending an email.

## Acceptance criteria

- Next.js 16's root `proxy.ts` runs only for `/auth` routes;
- an unconfigured environment passes through the proxy so the existing
  unavailable shell remains usable;
- a configured environment uses a cookie-aware `@supabase/ssr` client and
  calls `getClaims()` immediately after client creation to refresh a session;
- refreshed cookies and Supabase's no-cache headers reach both the request and
  browser response;
- `/auth/callback` handles an authorization code only with the existing
  server/cookie client;
- missing, failed, or unavailable callbacks return to the honest auth shell;
- `next` accepts only a same-origin relative path and cannot become an open
  redirect;
- the public auth shell keeps every sign-in control disabled and does not
  initiate password, OTP, or Google authentication.

## Exclusions

- no Google provider, password, or email OTP activation;
- no Supabase dashboard, Auth URL allowlist, SMTP, Vercel, or database change;
- no test user or public email delivery;
- no account menu, protected application route, cloud save, collection, note,
  form, or local-to-cloud import work;
- no catalogue or media change.

## Verification plan

- focused static tests cover the proxy matcher, config fallback, cookie/header
  forwarding, `getClaims()` verification, callback exchange, and redirect
  containment;
- run formatting, type, lint, Node tests, build, and the existing local auth
  route at desktop and mobile widths;
- inspect the complete diff for secret exposure, provider activation, and
  accidental scope expansion.

## Follow-up boundary

`10.2b` remains blocked for live provider activation. Google is intentionally
deferred. Password and email-code activation stay behind the Auth URL settings
and custom SMTP/domain work described in `docs/remaining-phase-plan.md`.

## Verification evidence

- focused auth shell, session transport, and Supabase client-contract tests
  passed;
- local browser checks at `1440px` and `390px` confirmed that `/auth` remains
  disabled and free of horizontal overflow;
- a local callback request with a missing code returned to
  `/auth?auth=link-invalid` and rejected an external `next` destination;
- `npm run format:check`, `npm run typecheck`, `npm run lint`, `npm test`, and
  `npm run build` passed. Lint retains the repository's existing
  non-blocking `expectedCount` warning in `scripts/catalogue-lib.mjs`;
- the build rendered the `/auth/callback` route and the root Next.js proxy.
