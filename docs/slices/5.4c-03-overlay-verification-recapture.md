# Slice 5.4c-03 — verified consent-overlay recapture

Status: **implementation and five-site recapture in progress**

## Goal

Recapture the five consent-obstructed resources from Slice 5.4c-02 without
expanding to the remaining catalogue and without weakening the non-consenting
interaction boundary.

The fixed targets are Webflow, Pixelbuddha, Framer, Relume, and Anima.

## Changes under test

- use fresh `agent-browser snapshot -i --json` accessibility refs, including
  iframe-inlined controls when available;
- select only exact reviewed rejection or necessary-only accessible names;
- permit one non-consenting preference-navigation action only when a visible
  consent overlay is detected;
- re-snapshot and re-audit after every click;
- classify a click as false positive when the control or consent overlay remains;
- expand protected-page vocabulary using the three missed Slice 5.4c-02 phrases;
- preserve 1440 × 756 capture, 960 × 504 WebP output, and the 307,200-byte cap.

## Safety boundary

The implementation contains no Accept, Agree, Allow all, consent-save, CAPTCHA,
login, paywall, access-control bypass, DOM deletion, CSS hiding, or screenshot
editing action.

## Acceptance criteria

- [ ] all five fixed targets produce terminal records;
- [ ] exact accessibility refs are used instead of unverified semantic fallback;
- [ ] successful click commands are independently verified against fresh state;
- [ ] false-positive clicks remain visibly rejected;
- [ ] every output is 960 × 504 WebP below 307,200 bytes;
- [ ] contact-sheet review decides suitability independently;
- [ ] no image enters production media automatically;
- [ ] the temporary workflow is removed after evidence collection;
- [ ] normal repository checks pass on the final cleaned diff.

## Decision gate

A broader catalogue run remains blocked until this recapture demonstrates that
post-click verification materially improves the five-site visual success rate.
