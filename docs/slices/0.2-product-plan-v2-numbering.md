Status: **documentation slice**

## Goal

Replace the active legacy `14.x` execution frame with Product Plan v2:

- Phase 0 records the completed direction reset;
- Phases 1–10 are the ten development phases;
- already merged work keeps its historical alias;
- future work uses phase/slice identifiers such as `2.2`;
- Git history and completed evidence are not rewritten.

## Acceptance criteria

- `docs/product-plan-v2.md` defines Phase 0 and Phases 1–10;
- `build-slices.md` is the active Product Plan v2 ledger;
- legacy `14.0`, `14.1`, and `14.2` map to completed Product Plan v2 work;
- Phase 1 is correctly marked complete;
- Phase 2 / Slice 2.1 is correctly marked complete;
- Phase 2 / Slice 2.2 is the only `NEXT` slice;
- README links to the new plan and reports current status;
- release-history tests verify the new ledger without deleting old deployment evidence;
- autonomous execution rules prohibit bypassing CI, inventing human evidence, or treating external blockers as completion;
- no runtime, schema, catalogue, dependency, provider, Supabase, or deployment configuration changes.

Phase 0 is the completed setup/reset and is not counted as one of the ten development phases.

## Autonomous boundary

The execution goal is continuous progress without routine approval between safe slices.

Autonomy does not permit:

- skipping the one-slice rule;
- bypassing failed checks;
- merging unsafe or unrelated changes;
- inventing human-review scores;
- fabricating provider verification;
- enabling external services without credentials/security readiness;
- exposing secrets or private/client data;
- copying restricted content;
- claiming deferred or blocked work is complete.

A real blocker is recorded as `BLOCKED`, with the smallest external action required.
