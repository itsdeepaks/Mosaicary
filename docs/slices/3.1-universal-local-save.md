# Product Plan v2 — Phase 3 / Slice 3.1

## Goal

Make browser-local resource Save available and consistent across canonical Browse, Source Detail, collection/playbook resource lists, and the Saved workspace without requiring an account or changing cloud state.

## Acceptance criteria

- the existing stable-ID store remains the canonical browser-local source of truth;
- legacy Tessli and Mosaicary URL-list migration remains supported without deleting legacy values;
- Browse card, list, and table views retain independent Save controls;
- every Source Detail page retains a Save control;
- every collection resource card gains the same persistent Save control;
- the Saved workspace reflects changes and retains clear/undo behaviour;
- writes notify other mounted Tessli save surfaces in the same document as well as other tabs;
- Save controls use `aria-pressed`, meaningful labels, and polite announcements;
- storage denial/corruption degrades to an empty private workspace without throwing;
- no account, network request, cloud sync, catalogue mutation, or new dependency is introduced.

## Exclusions

- no project Boards or notes;
- no collection-level saving;
- no cloud persistence or local-to-cloud merge;
- no authentication activation;
- no Saved search/filter redesign;
- no playbook content conversion;
- no catalogue/profile/schema change.

## Expected files

- `web/components/saved-resources/save-store.ts`;
- `web/components/collection-resources/collection-resource-list.tsx`;
- `web/app/collections/[slug]/page.tsx`;
- focused save-store and collection tests;
- `build-slices.md` completion ledger after implementation validation.

## Rollback

Revert the slice squash commit. The existing v2 local-storage key and legacy keys are retained, so saved IDs remain recoverable.
