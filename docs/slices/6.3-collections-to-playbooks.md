# Product Plan v2 — Phase 6 / Slice 6.3

Status: **DONE**

## Goal

Convert Tessli's six repository-maintained Collections into staged Playbooks that tell a researcher what outcome they are pursuing, who the path is for, what to inspect at each stage, and which decision each source helps make.

## Route and compatibility decisions

- `/collections` and `/collections/[slug]` remain the canonical URLs in this slice;
- public navigation and page copy use `Playbooks` while existing links, machine-readable routes, and indexed URLs remain stable;
- the canonical repository collection source advances to schema version 2 rather than introducing page-only guidance;
- the same ordered Playbook truth powers the website and public JSON/Markdown representations;
- existing collection IDs, slugs, resource membership, editorial order, review dates, and status remain stable;
- a source appears exactly once across one Playbook's stages;
- Playbooks provide research guidance, not popularity, ranking, sponsorship, or universal-best claims.

## Canonical Playbook fields

Each published Playbook adds:

- `outcome` — the concrete research result;
- `audience` — the intended researcher or project context;
- `stages` — two to four ordered stages;
- each stage has a stable ID, title, inspection objective, supported decision, and ordered items;
- each item references one existing `resourceId` and records a concise `role` explaining why the source is included.

## Acceptance criteria

- all six existing published Collections validate as version-2 Playbooks;
- every existing member resource is assigned to exactly one stage and no unknown member is introduced;
- stage item order reconstructs the existing canonical `resourceIds` order;
- the Playbooks index explains the staged workflow and retains truthful repository counts;
- each detail route shows outcome, audience, review date, ordered stages, source roles, inspection objectives, and supported decisions;
- source cards retain Save and existing source-detail/visit behavior;
- Playbooks link to project Boards and their public JSON/Markdown representations;
- navigation/footer labels become `Playbooks` without changing canonical URLs;
- public collection JSON/Markdown advances version truthfully and preserves bounded editorial order;
- sitemap/static route behavior remains stable;
- mobile and desktop Playbook layouts have no horizontal overflow or duplicated result trees;
- schema, generator, drift, unit, route, public representation, accessibility, browser, build, CI, and release gates pass.

## Exclusions

- no new seventh Playbook;
- no source membership, catalogue-profile, verification, ranking, or media change;
- no homepage redesign;
- no automatic Board mutation or bulk localStorage write;
- no account, cloud, collaboration, auth, provider, credential, analytics, or submission change;
- no redirects away from `/collections`;
- no Pattern Candidate or UI-taste claim.

## Expected files

- collection schema and repository source data;
- release-catalogue validation and generated catalogue output;
- collection/Playbook model and public representation formatter;
- Playbooks index/detail presentation and styles;
- navigation/footer terminology;
- focused schema, generation, representation, route, and browser tests;
- ledger/evidence updates after exact-head validation.
