# Slice 14.1 — minimum source-profile and coverage-level contract

Status: **implementation complete — repository validation pending**

## Goal

Create one canonical source-profile contract that preserves the existing 295-row
catalogue, links the 20 structured intelligence profiles, and exposes honest
`Listed`, `Profiled`, and `Verified` coverage semantics without redesigning the
website or changing the MCP tool allowlist.

## Contract

Every catalogue resource now composes into one `SourceProfile` with:

- stable catalogue ID and slug;
- name, canonical URL, domain, description, and category;
- Tessli source-type classification with an explicit
  `category-classification` basis;
- access, subscription, and availability status;
- one coverage record containing level, reason, profile status, last verification
  date, evidence confidence, human-review status, freshness status, and evidence
  count;
- the existing structured intelligence profile or `null`.

The JSON Schema is `schemas/source-profile.schema.json`. The shared runtime
adapter is `web/lib/source-profiles.ts` and is suitable for website and MCP
consumers.

## Coverage semantics

### Listed

Catalogue identity and access metadata exist, but there is no linked structured
intelligence profile.

### Profiled

Structured intelligence and evidence exist, but the full Verified contract is
incomplete.

### Verified

Structured intelligence, evidence, verification date, confidence, and an
explicit completed human-review record all exist.

A legacy intelligence profile with `status: verified` does **not** automatically
become Verified coverage. The existing 20 profiles do not record explicit human
review, so the truthful Slice 14.1 baseline is:

- **275 Listed**;
- **20 Profiled**;
- **0 Verified**.

This preserves the historical profile status while preventing a stronger public
coverage claim than the repository can prove.

## Deterministic classifications

Source type is a Tessli classification derived from the canonical catalogue
category. It is not represented as a provider claim. The mapping covers all 11
existing categories and is versioned in the source-profile module.

Freshness is calculated against the fixed contract review date `2026-08-04`:

- current: 0–90 days;
- aging: 91–180 days;
- stale: more than 180 days;
- unknown: missing, invalid, or future verification date.

Evidence confidence is aggregated conservatively:

- `certain` only when every evidence item is certain;
- `likely` when all evidence is known and at least one item is likely;
- `unknown` when evidence is absent or contains an unsupported confidence value.

## Compatibility boundary

- the canonical catalogue file and generated catalogue composition are unchanged;
- the 20 intelligence JSON files and their strict schema are unchanged;
- existing website code can consume `getAllSourceProfiles` or
  `getSourceProfile` without changing catalogue identity;
- existing MCP resolution continues to return the same resource and intelligence
  records for stable IDs and slugs;
- no visible badge, source detail route, search redesign, auth, cloud persistence,
  screenshot pipeline, or external provider integration is added.

## Validation

`web/scripts/check-source-profile-contract.mjs` verifies:

- the schema ID and contract version;
- one source profile for each of 295 catalogue resources;
- stable ID and slug uniqueness;
- exact preservation of catalogue identity fields;
- complete 11-category source-type classification;
- intelligence linkage by stable ID or slug;
- evidence counts and verification dates;
- no verification claims on Listed resources;
- no Verified coverage without explicit human review;
- deterministic `275 / 20 / 0` coverage composition;
- website-ready and MCP-compatible identifier resolution.
