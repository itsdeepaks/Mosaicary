# Product Plan v2 / Slice 2.2 — Canonical Browse Implementation

Status: **IN PROGRESS**  
Depends on: Phase 2 / Slice 2.1 Browse contract  
Branch: `feat/canonical-browse`

## Goal

Replace the competing Explore and Full Reference catalogue experiences with one paginated, shareable, responsive `/resources` browser that evaluates a Tessli source internally before sending a visitor to the provider.

## Acceptance criteria

- `/resources` is the only complete source browser;
- server derivation sends only the selected result page to interactive result views;
- cards render at most 24 results;
- compact list and table render at most 50 rows;
- URL state restores query, category, access, source type, profile level, sort, view, and page;
- invalid/default/legacy URL state normalizes deterministically;
- changing query/filter/sort/view resets page to one;
- browser Back and Forward restore canonical state;
- only the selected result view is rendered;
- no duplicate full mobile/desktop result map exists;
- `Recently verified` is omitted while the canonical baseline contains zero Verified sources;
- old `sort=verified` does not create a fake verification order;
- hard-coded verification dates are removed;
- cards, list, and table have distinct responsibilities;
- internal `/resources/[slug]` navigation is primary;
- Save remains independent and works in every result view;
- Visit source remains a separate safe external action;
- unavailable sources retain an internal profile and do not expose a misleading provider action;
- homepage search submits to `/resources`;
- homepage catalogue rendering is reduced to a maximum of twelve compatibility-preview results;
- legacy useful query state is preserved when moving to `/resources`;
- search, pagination, internal navigation, and external navigation remain useful without JavaScript;
- empty, pending, error, and out-of-range page states are truthful;
- focus, result count, pagination, table, filter sheet, and view controls are accessible;
- 1440, 1024, 768, 390, and 320 px checks pass without overflow;
- focused tests, full Web CI, release gate, complete diff review, and browser evidence pass.

## Expected areas

- canonical Browse parser/serializer and result derivation;
- server-side pagination;
- `/resources` route and metadata;
- shared Browse controls;
- card, compact-list, and table result renderers;
- minimum truthful internal source-profile route boundary if needed to prevent dead links;
- homepage search and bounded-preview migration;
- global route naming only where required by canonical ownership;
- unit, route, component, accessibility, history, responsive, and no-JavaScript checks;
- this slice evidence.

## Exclusions

- no mature Source Detail content beyond the minimum non-dead boundary;
- no universal Compare;
- no semantic/vector search;
- no new profiles merely to populate filters;
- no live provider verification;
- no local Boards or research-pack export;
- no authentication, cloud, submission, or moderation work;
- no mature homepage redesign;
- no new MCP tools;
- no mass screenshot work;
- no unrelated refactor;
- no dependency unless a complete-diff review proves an existing capability cannot safely satisfy the contract.

## Rollback

Revert the squash commit. The repository-managed catalogue, source-profile contract, Saved data format, MCP, Supabase groundwork, and deployment history must remain independently recoverable.
