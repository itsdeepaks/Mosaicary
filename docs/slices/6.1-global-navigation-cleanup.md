# Product Plan v2 — Phase 6 / Slice 6.1

Status: **DONE**

## Goal

Make Tessli's public navigation describe the implemented product truth: one canonical Browse surface, reusable Collections, and local research utilities without duplicate names or premature account/For AI promotion.

## Product decisions

- the wordmark remains the route to the homepage;
- `Browse` routes to canonical `/resources`;
- `Collections` remains a primary research route until Slice 6.3 replaces its framing with Playbooks;
- `Search` is a utility that routes to the canonical Browse search field;
- `Saved` remains a utility route;
- `About` and policy/contribution routes remain secondary in the footer;
- `Sign in` is removed from the public shell until authentication is an implemented product capability;
- `For AI` is not placed in public navigation during this slice because Slice 6.4 has not delivered a working route yet;
- `/`, `/resources`, and the legacy internal route behavior remain stable; this slice changes public naming and promotion, not canonical data or route migrations.

## Acceptance criteria

- desktop and mobile primary navigation expose only `Browse` and `Collections`;
- utility navigation exposes `Search` and `Saved` with working destinations;
- the canonical Browse search control has a stable fragment target;
- `Explore`, duplicated `Resources`, and `Full reference` labels disappear from the public shell;
- `About` moves out of primary navigation and remains available in the footer;
- public desktop and mobile `Sign in` entry points are removed without deleting or redesigning the existing auth route;
- `For AI` is absent until Slice 6.4 creates its working destination;
- active-route behavior remains correct for `/resources`, `/collections`, and `/saved`;
- the accessible mobile modal, focus containment, Escape handling, scroll lock, inert content boundary, and desktop breakpoint behavior remain intact;
- all public navigation targets resolve successfully;
- header/footer layouts remain coherent without horizontal overflow across desktop and mobile evidence widths;
- focused tests, full tests, production build, Web CI, and release gate pass.

## Delivered implementation

- one primary navigation group with `Browse` and `Collections`;
- one utility navigation group with `Search` and `Saved`;
- matching mobile primary and utility groups inside the existing modal sheet;
- public account promotion removed while the isolated `/auth` route and its implementation remain untouched;
- no premature `For AI` link before Slice 6.4 supplies a working destination;
- stable `#browse-search` fragment on canonical Browse;
- footer research group for Browse, Collections, Saved, and project Boards;
- About, contribution, and legal routes retained as secondary footer navigation;
- duplicate public-shell labels removed without changing canonical catalogue or legacy route behavior;
- focused unit/contract coverage and a dedicated CDP browser matrix.
