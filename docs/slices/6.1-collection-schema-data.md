# Slice 6.1 — Repository-maintained collection schema and launch data

Status: **done**

## Goal

Introduce one deterministic, reviewable source of truth for Tessli's public launch collections and merge it into the validated catalogue output without beginning the Collections UI.

## Acceptance criteria

- collection source data is committed in the repository and reviewed independently from generated output;
- source shape is validated before catalogue generation;
- exactly six launch collections cover the approved workflows: SaaS landing-page references, typography and font tools, motion starter pack, open-source UI libraries, accessible colour tools, and design systems worth studying;
- every collection has a stable unique ID and slug, factual title and description, approved cover style, published status, and ISO last-reviewed date;
- collection resource IDs reference existing catalogue resources only;
- resource IDs are unique within each collection and preserve intentional editorial order;
- published launch collections contain a useful minimum set of resources and no empty collection;
- no curator identity, popularity, trend, save count, or activity is invented;
- deterministic catalogue generation includes the validated collections;
- validation fails for unknown resource IDs, duplicate collection IDs/slugs, duplicate members, invalid dates/status/styles, or malformed source data;
- invalid collection sources produce blocking errors and zero publishable collections rather than partial output or a crash;
- validation report records collection count and source provenance without changing the original 295-row CSV provenance;
- committed catalogue and validation report match regenerated output exactly;
- formatting, types, lint, Node tests, catalogue drift, production build, and existing browser regressions pass;
- `build-slices.md` records `6.1 DONE / 6.2 NEXT` only after final verification.

## Exclusions

- no `/collections` or `/collections/[slug]` UI;
- no collection cards, cover artwork, search, filters, or navigation changes;
- no user-created/private collections;
- no collection saving or browser storage;
- no Supabase tables or authentication;
- no resource metadata enrichment, screenshots, or external requests;
- no catalogue resource, category, access, description, tag, or media changes;
- no dependency or lockfile change;
- no production cutover.

## Data decision

The raw CSV migration remains unchanged and still emits no collections. The application-facing release catalogue composes a separately reviewed collection source through `web/scripts/release-catalogue-lib.mjs`, preserving CSV provenance while validating collection shape and resource-ID relationships.
