# Product Plan v2 — Phase 3 / Slice 3.2

## Saved workspace search/filter refinement

Status: **complete pending exact-head merge gates**

## Goal

Make a growing browser-local shortlist usable without introducing a second persistence model or crossing into project Boards.

## Acceptance criteria

- search saved resources by name, domain, description, use case, and tags;
- filter by categories and access models represented in the saved set;
- sort by recent saved order, name A–Z, or name Z–A;
- show truthful filtered result counts and a distinct no-match state;
- clear derived filters without mutating persisted saved IDs;
- offer Undo after removing one saved resource;
- retain clear-all confirmation and reversible clear;
- preserve the stable-ID store, both legacy migrations, same-document synchronization, and cross-tab synchronization;
- link the empty workspace to canonical `/resources`;
- provide labelled, keyboard-accessible, responsive controls without supported-width overflow.

## Implementation

- `web/components/saved-resources/saved-resources-experience.tsx`
- `web/components/saved-resources/saved-resources.module.css`
- `web/tests/saved-resources-page.test.mjs`

## Data and security boundary

The saved-ID list remains the only persisted state. Search, category, access, and sorting are client-derived state and are not written to storage.

This slice adds no:

- network request;
- account or authentication dependency;
- Supabase or cloud persistence;
- project Board or notes model;
- sharing, collaboration, or analytics;
- catalogue, source-profile, or schema mutation;
- dependency or deployment change.

## Review findings fixed

1. Initial implementation did not match repository formatting; the repository Prettier configuration was applied.
2. The existing Saved test incorrectly banned the word `collection`, despite collections being an approved universal Save surface. The boundary assertion now bans the actual excluded systems and directly tests the new controls and undo behaviour.
3. Temporary formatting and ledger workflows were removed before final review.
4. Derived filters and sort state remain in component state only; persisted stable-ID order is not rewritten.
5. Individual removal and clear-all remain independently reversible.
