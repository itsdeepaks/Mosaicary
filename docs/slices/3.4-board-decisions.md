# Phase 3 / Slice 3.4 — Board decisions and unresolved questions

Status: implemented on `agent/phase-3-4`

## Goal

Extend browser-local project Boards so research choices remain explicit before research-pack export.

## Acceptance criteria

- every Board source records `undecided`, `selected`, or `rejected`;
- every source may retain a separate decision rationale and research note;
- Boards retain editable unresolved questions;
- existing `tessli-project-boards-v1` data migrates in place without loss;
- malformed records continue to degrade safely;
- same-document and cross-tab synchronization remain intact;
- controls remain labelled, keyboard-operable, responsive, and local-only;
- no research-pack export, authentication, cloud sync, sharing, collaboration, catalogue, profile, dependency, provider, credential, or deployment-state change.

## Persistence decision

The storage key remains `tessli-project-boards-v1`. The parser normalizes older valid records by adding:

```text
decision: undecided
rationale: ""
unresolvedQuestions: []
```

This is an additive read-time migration. It avoids invalidating existing local Boards merely because optional decision fields were introduced.

## Data boundary

- source facts remain in the canonical source profile;
- research notes remain user-authored observations;
- decision and rationale remain project judgment;
- unresolved questions remain explicitly open;
- no private Board content is transmitted or published.

## Exclusions

Phase 4 export work is intentionally excluded. This slice records the structured inputs that a later export contract may consume.

## Rollback

Revert the slice. Existing Boards containing the additive fields remain valid JSON; the prior parser would ignore the whole records because the item shape changed, so rollback should also preserve or explicitly migrate local data before public release.
