# Slice 13.5 — Read-only Tessli MCP over native metadata

Status: **IN PROGRESS — implementation complete; helper-free full CI pending**  
Base commit: `55e7126ef52ae23065d0336e71973e3da53424b5`

## Goal

Expose Tessli's repository-managed catalogue, collections, intelligence profiles, and deterministic research-packet builder to local coding agents through a read-only Model Context Protocol server.

The first Tessli MCP is a local stdio process. It is not a hosted API, provider proxy, screenshot service, account feature, or write path.

## Implemented tools

1. `search_resources` — bounded native search and profile-aware filtering.
2. `get_resource_profile` — resolve one catalogue resource and its repository intelligence profile.
3. `compare_resources` — compare two to five native resources with capability, workflow, limitation, governance, and verification metadata.
4. `get_collection` — return one published collection and its ordered native resources.
5. `build_research_plan` — create a deterministic source-selection plan from one to ten repository resources.
6. `create_reference_packet` — reuse Slice 13.4 to return a deterministic Markdown handoff packet.
7. `verify_resource` — report only repository-recorded evidence and verification state; perform no live network verification.

## Acceptance criteria

1. The server uses local stdio transport and keeps stdout reserved for MCP JSON-RPC messages.
2. The implementation uses an exact-pinned maintained MCP SDK and validation dependency compatible with Tessli's existing Node 22 and TypeScript 5 contract.
3. Every tool has an explicit input schema, bounded inputs, read-only annotations, and a structured result.
4. Tool results derive only from committed Tessli catalogue, collection, intelligence-profile, and packet-builder data.
5. Search is deterministic, caps returned rows, and may filter by native category/access plus profile capability, framework, integration method, and workflow fit.
6. Resource and collection identifiers resolve by stable ID or slug without inventing aliases.
7. Comparison accepts two to five unique resources and preserves the caller's order.
8. Research planning and packet export accept at most ten unique resources.
9. `create_reference_packet` reuses the existing Slice 13.4 implementation rather than creating a second export model.
10. `verify_resource` clearly states that no live check occurred and returns source/evidence dates already recorded in the repository.
11. Unknown identifiers and invalid bounds fail as safe tool-level or schema errors without exposing stack traces.
12. A real stdio client integration test lists the exact tool allowlist and calls representative tools successfully.
13. Unit tests cover deterministic search, filtering, identifier resolution, comparison, collection order, planning, packet export, verification boundaries, and limits.
14. The server makes no network request, reads no credential, writes no file/database, and exposes no HTTP listener.
15. No provider adapter, Landingfolio token/call, screenshot, remote media retrieval, user/account data, Supabase, auth, or forms enter the slice.
16. Normal application formatting, typecheck, lint, tests, catalogue drift, production build, browser regression checks, release gate, and Vercel preview remain green.
17. The complete diff contains only the MCP implementation, exact dependencies/lockfile, focused tests, operator documentation, slice note, and final ledger status.

## Dependency decision

Use the maintained v1 SDK line for this slice rather than migrating the application to the newly split v2 packages. The v2 server package requires a TypeScript 6 consumer contract; upgrading TypeScript and resolving application-wide effects is unrelated to a read-only MCP vertical slice.

Exact production dependencies:

- `@modelcontextprotocol/sdk@1.30.0`
- `zod@4.4.3`

## Security and data boundary

- local process only;
- no listening socket;
- no environment-based secret or token;
- no `fetch` or provider request;
- no roots/project-code ingestion;
- no arbitrary file read;
- no database or browser storage;
- no mutation tool;
- no unrestricted result size;
- no third-party binary or rendered content;
- native and Tessli-authored metadata only;
- external claims retain source and verification metadata from intelligence profiles.

## Exclusions

- no Streamable HTTP deployment;
- no public `/mcp` endpoint;
- no authentication or per-user rate limit because there is no remote multi-user transport;
- no provider adapter framework;
- no Landingfolio official-MCP experiment;
- no external provider search;
- no screenshot or component retrieval;
- no account/private collection/notes access;
- no catalogue or intelligence-profile content enrichment;
- no UI route or component;
- no TypeScript 6 migration;
- no unrelated dependency update.
