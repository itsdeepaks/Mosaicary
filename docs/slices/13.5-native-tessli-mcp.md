## Goal

Expose Tessli's repository-managed catalogue, collections, intelligence profiles, and deterministic research-packet builder to local coding agents through a read-only Model Context Protocol server.

The first Tessli MCP is a local stdio process. It is not a hosted API, provider proxy, screenshot service, account feature, or write path.

## Implemented tools

1. `search_resources` — bounded native search and profile-aware filtering.
2. `get_resource_profile` — resolve one catalogue resource and its repository intelligence profile.
3. `compare_resources` — compare two to five native resources with capability, workflow, limitation, governance, and verification metadata.
4. `get_collection` — return one published collection and its ordered native resources.
5. `build_research_plan` — create a deterministic source-selection plan from one to ten repository resources.
6. `create_reference_packet` — reuse Slice 13.4 to return a deterministic Markdown handoff packet.
7. `verify_resource` — report only repository-recorded evidence and verification state; perform no live network verification.

## Dependency and lockfile review

The generated lockfile is intentionally retained rather than hand-edited. Most additions are the MCP SDK v1 transitive graph and shared packages moving from development-only to production classification. Some transitive packages support SDK transports that Tessli does not import; their presence in the package graph does not create an HTTP listener. The implemented server imports only the MCP server core and stdio transport, and focused security tests enforce the local read-only boundary.

The maintained v1 SDK line was selected instead of migrating Tessli to the newly split v2 packages because the v2 server package requires a TypeScript 6 consumer contract. A TypeScript migration and its application-wide effects are outside this vertical slice.

Exact production dependencies:

- `@modelcontextprotocol/sdk@1.30.0`
- `zod@4.4.3`

Repository production build, browser checks, and release gate all passed, so this external quota condition is documented and does not justify a code change. A future Vercel-triggering commit or manual redeploy can create the preview after the account window resets.
