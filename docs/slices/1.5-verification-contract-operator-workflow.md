# Product Plan v2 — Slice 1.5 Verification Contract and Operator Workflow

Status: **DONE**

## Goal

Define and execute the repository contract required to review one Profiled source for possible Verified promotion without changing current coverage.

This slice creates the verification record, deterministic draft/check workflow, reviewer and evidence rules, and safe failure behavior. It does not promote any source.

Coverage must remain:

```text
255 Listed
40 Profiled
0 Verified
```

## Acceptance criteria

- define versioned `tessli.resource-verification.v1` JSON Schema;
- bind every verification record to one canonical source ID/slug and one SHA-256 fingerprint of the reviewed intelligence profile;
- require an explicit `human-operator` reviewer identity;
- represent provider availability, claim-level evidence checks, documented agent-interface checks, governance checks, limitations review, freshness/recheck date, and final decision;
- distinguish draft, completed-needs-review, rejected, and completed-verified outcomes;
- create a deterministic local command that drafts a record from canonical source/profile truth without network access;
- create a deterministic local command that validates schema, source identity, profile fingerprint, review completeness, date ordering, and Verified decision gates;
- reject unknown sources, Listed-only sources, stale profile fingerprints, blank reviewer IDs, incomplete checks, contradictions, and unsafe Verified decisions with actionable errors;
- never read credentials, call providers, mutate profiles, or promote coverage automatically;
- provide an operator handbook with the exact manual evidence and review sequence;
- add focused tests for deterministic draft bytes, validation failures, safe completed-needs-review records, and Verified eligibility;
- preserve website, public representation, MCP, catalogue, and coverage behavior at `255 / 40 / 0`;
- complete formatting, typecheck, lint, tests, catalogue drift, build, browser, and release gates;
- mark Slice 1.5 DONE and Slice 1.6 NEXT only after exact-head validation and complete-diff review.

## Exclusions

- no source becomes Verified;
- no completed provider check, human review, or review date is invented;
- no live browser, HTTP, API, CLI, MCP, pricing, terms, licence, credential, or availability call is automated;
- no provider credentials, cookies, tokens, private content, screenshots, binaries, or workspace data are stored;
- no intelligence-profile schema rewrite or retroactive status change;
- no Browse, Source Detail, For AI, homepage, Pattern Candidate, auth, cloud, forms, moderation, analytics, email, or deployment change;
- no new runtime dependency.

- a pure verification library under `web/lib/`;

- bounded Product Plan, ledger, README, and release-contract updates after validation.

## Governance boundary

A verification record is repository review evidence, not permission to copy provider content and not proof that a provider will remain available. Operator checks must use user-owned credentials where credentials are legitimately required, retain no secrets, and record only bounded observations and source links.

Only a completed record with a human operator, current profile fingerprint, passed availability check, confirmed claims, reviewed interfaces/governance/limitations, valid dates, and a `verified` decision may become eligible for Slice 1.6 promotion. Eligibility does not itself mutate coverage.

## Validation evidence

The completed implementation demonstrated:

- locked Ajv 8 / Draft 2020-12 schema compilation with explicit calendar-date and URI formats;
- formatting, TypeScript, lint, and all 222 repository tests passing;
- deterministic CLI creation and validation of temporary draft, completed-needs-review, and completed-verified records;
- rejection of impossible dates, stale fingerprints, contradictory evidence, unknown or duplicate CLI options, unsafe Verified records, and extra secret-bearing fields;
- catalogue drift, production build, canonical browser matrix, and Phase 1 Release Gate passing;
- complete changed-file and review-thread inspection with no credentials, cookies, private provider responses, proprietary assets, or workspace content added;
- unchanged canonical coverage: `255 Listed / 40 Profiled / 0 Verified`.

## Rollback

Revert the schema, handbook, local verification library/CLI, tests, package scripts, and bounded authority updates. No source record, coverage level, provider, credential, or external state requires rollback.
