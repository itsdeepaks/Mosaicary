# Slice 5.4c-02 — interaction-aware screenshot pilot

Status: **implementation and live validation in progress**

## Goal

Test a controlled browser workflow against fifteen deliberately mixed public
websites before authorizing screenshot capture for the remaining Tessli
catalogue.

This slice extends the five-site storage pilot with explicit viewport control,
safe consent rejection, dismissible-overlay handling, challenge-page detection,
immutable versioned Storage paths, and before/after interaction evidence.

## Test set

The fixed set contains:

- Figma and Webflow, which exposed an event banner and cookie overlay in the
  first pilot;
- UI8 and Creative Market, which previously returned HTTP 403 to metadata
  discovery;
- Penpot, Framer, and Plasmic, whose HTML exceeded the bounded metadata ceiling;
- Pixelbuddha, UI Store Design, v0, Replit, and Anima, whose declared media was
  misleading, sparse, campaign-oriented, heavy, or oversized;
- Relume and Builder.io as representative comparison cases;
- Webstudio as a known-good screenshot control.

The exact resource IDs, catalogue URLs, and reasons are fixed in the capture
script. No arbitrary URL input is accepted.

## Interaction policy

The browser may click only a reviewed non-consenting action inside a visible
fixed, sticky, modal, or dialog container:

- Reject all;
- Reject optional;
- Decline all;
- Only necessary;
- Continue without accepting;
- Do not consent;
- No thanks;
- an explicitly labelled Close or Dismiss control.

The script does not contain Accept, Agree, Allow all, or equivalent consenting
actions. A fallback exact-text search is limited to rejection or necessary-only
phrases for consent interfaces rendered inside frames.

Every page records:

- browser command outcomes;
- overlay audit before interaction;
- every attempted dismiss action;
- overlay audit after interaction;
- final URL and title when available;
- challenge-page terms such as access denied or verify you are human;
- raw and optimized byte sizes;
- quality, SHA-256, upload response, and public-read status.

## Capture and Storage contract

- browser: agent-browser with its managed Chrome;
- viewport: **1440 × 756**;
- output: **960 × 504 WebP**;
- maximum object size: **307,200 bytes**;
- batch: `interaction-v1-20260803`;
- immutable path:
  `review/interaction-v1-20260803/<resource-id>.webp`;
- overwrite: forbidden;
- bucket: existing public `resource-previews` bucket;
- direct Storage insert policies: none.

The temporary Supabase uploader validates GitHub Actions' OIDC identity against
GitHub's public signing keys. It accepts only this repository, the exact pilot
branch, the exact batch, the fifteen resource IDs, valid WebP bytes, and the size
ceiling. No upload secret or Supabase privileged key is stored in GitHub.

## Acceptance criteria

- [ ] all fifteen resources produce a terminal captured or failed record;
- [ ] infrastructure succeeds even when individual websites reject automation;
- [ ] successful screenshots are exactly 960 × 504 WebP and below 307,200 bytes;
- [ ] Figma and Webflow demonstrate whether overlay handling improved the first
      captures;
- [ ] challenge and block pages remain visible and are flagged rather than
      bypassed;
- [ ] no consenting cookie action exists in code or recorded interactions;
- [ ] all successful uploads use immutable versioned object paths;
- [ ] artifact contains raw images, optimized images, contact sheet, manifest,
      run log, and canonically formatted source;
- [ ] human visual review decides suitability independently for every image;
- [ ] no pilot image enters production `resource-media.json` automatically;
- [ ] normal tests, catalogue checks, build, and browser smoke checks pass;
- [ ] temporary workflow and uploader are closed after evidence collection;
- [ ] Supabase security advisors remain clear.

## Exclusions

- no capture for every remaining catalogue resource;
- no CAPTCHA, anti-bot, login, paywall, region gate, or access-control bypass;
- no DOM deletion, CSS hiding, or screenshot editing to conceal an obstruction;
- no automatic production approval;
- no overwrite of approved or prior pilot media;
- no database table for image bytes;
- no card UI, auth, user-data, or catalogue-content change.

## Decision gate

A larger screenshot run may begin only if this batch establishes an acceptable
capture and visual-suitability rate and exposes manageable classes of remaining
failures. The next implementation must preserve manual contact-sheet review and
immutable Storage objects.
