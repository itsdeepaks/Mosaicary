# Slice 5.4c-02 — interaction-aware screenshot pilot

Status: **pilot complete — unattended catalogue rollout not approved**

## Goal

Test a controlled browser workflow against fifteen deliberately difficult public
websites before authorizing screenshot capture for the remaining Tessli
catalogue.

This slice extends the five-site Storage pilot with explicit viewport control,
safe non-consenting interactions, challenge-page preservation, immutable
versioned Storage paths, compression evidence, and human contact-sheet review.

## Test set

The fixed set contains:

- Figma and Webflow, which exposed an event banner and cookie overlay in the
  first pilot;
- UI8 and Creative Market, which previously returned HTTP 403 to metadata
  discovery;
- Penpot, Framer, and Plasmic, whose HTML exceeded the bounded metadata ceiling;
- Pixelbuddha, UI Store Design, v0, Replit, and Anima, whose declared media was
  misleading, sparse, campaign-oriented, heavy, or oversized;
- Relume and Builder.io as representative comparison cases;
- Webstudio as a known-good screenshot control.

The exact resource IDs and catalogue URLs are fixed in the capture script. No
arbitrary URL input is accepted.

## Interaction policy

The browser may click only a reviewed non-consenting action inside a visible
fixed, sticky, modal, or dialog container:

- Reject all;
- Reject optional;
- Decline all;
- Only necessary;
- Continue without accepting;
- Do not consent;
- No thanks;
- an explicitly labelled Close or Dismiss control.

The script contains no Accept, Agree, Allow all, or equivalent consenting action.
It never deletes page elements, hides overlays through CSS, edits the screenshot,
or attempts CAPTCHA or access-control bypass.

## Capture and Storage contract

- browser: `agent-browser 0.27.0` with managed Chrome;
- viewport: **1440 × 756**;
- output: **960 × 504 WebP**;
- maximum object size: **307,200 bytes**;
- batch: `interaction-v1-20260803`;
- immutable path:
  `review/interaction-v1-20260803/<resource-id>.webp`;
- overwrite: forbidden;
- bucket: existing public `resource-previews` bucket;
- direct Storage insert policies: none.

The temporary Supabase uploader validated GitHub Actions OIDC against GitHub's
public signing keys and required the expected issuer, audience, repository,
exact branch or PR ref, batch, fifteen resource IDs, valid WebP bytes, and size
ceiling. No upload secret or privileged Supabase key was stored in GitHub.

### Terminal blocked evidence

- UI8 served `Sorry, you have been blocked`;
- Creative Market served a security-verification page;
- Replit served `Sorry, you have been blocked`.

These states were captured and rejected without bypass attempts. The text-only
challenge detector missed these three visually obvious states, proving that
contact-sheet review remains mandatory.

## Concurrency finding

The temporary workflow was triggered by both branch push and pull request. Both
runs used the same immutable prefix. Twelve reviewed artifact sizes match the
stored object exactly; Creative Market, UI Store Design, and Framer differ because
the earlier concurrent run won the first-write race.

No object was overwritten. The production design must use one execution trigger
per batch and one unique versioned prefix per approved run.

## Decision

The capture, compression, OIDC, and Storage architecture is viable. The **46.7%**
visual suitability rate on this intentionally difficult batch is not sufficient
for an unattended all-catalogue run.

Before the next broader batch, the capture implementation should:

1. run from one workflow trigger per immutable batch;
2. inspect iframe accessibility trees for rejection controls;
3. include reviewed exact actions such as `Reject` and
   `Reject non-essential cookies`;
4. verify that an overlay disappeared after a click;
5. expand block detection to `Sorry, you have been blocked`, `unable to access`,
   and `performing security verification`;
6. preserve terminal blocked states;
7. require contact-sheet approval before production media publication.

## Exclusions preserved

- no capture for every remaining catalogue resource;
- no CAPTCHA, anti-bot, login, paywall, region gate, or access-control bypass;
- no DOM deletion, CSS hiding, or screenshot editing;
- no automatic production approval;
- no database table for image bytes;
- no card UI, auth, user-data, generated catalogue, or catalogue-content change.

## Production boundary

The seven suitable images remain review candidates only. Publication requires a
separate slice that copies explicitly approved Supabase URLs into production
media records and reruns catalogue, UI, and browser validation.
