# Slice 9.2a — Pause automatic Vercel Git deployments

## Goal

Continue Tessli development through local development and GitHub Actions without consuming Vercel deployment capacity on every branch push or merge.

This is a temporary delivery-policy change. It does not delete the Vercel project, remove production domains, or claim that Slice 9.3 production replacement has occurred.

## Acceptance criteria

- Root `vercel.json` uses the current Vercel configuration schema.
- `git.deploymentEnabled` is explicitly `false` for every branch.
- Existing clean-URL and browser-security header behaviour remains unchanged.
- A repository test parses `vercel.json` and locks the paused-deployment and security-header contracts.
- GitHub Actions remains the required validation environment for branches and pull requests.
- Slice 9.3 remains blocked until the Vercel project and rollback target are accessible.
- Re-enabling deployment requires an intentional reviewed change in the production-cutover slice.

## Exclusions

- no Vercel project deletion;
- no deletion of existing deployments;
- no production-domain or DNS changes;
- no project-root, framework, install, build, or output-setting changes;
- no Supabase, authentication, catalogue, schema, or UI work;
- no production deployment or promotion.

## Development workflow while paused

Use the normal repository slice loop. Branches and pull requests continue to run GitHub Actions, including Web CI and the Phase 1 Release Gate where their path filters apply.

Developers can run the application locally from `web/`:

```bash
npm ci
npm run dev
```

Before merge, run:

```bash
npm run format:check
npm run typecheck
npm run lint
npm test
npm run catalogue:check
npm run build
```

## Re-enable procedure

Only Slice 9.3 may re-enable automatic deployment. Before changing `git.deploymentEnabled`, that slice must record:

1. the accessible Tessli Vercel project and owning team;
2. current project root and framework/build configuration;
3. current production domains;
4. the previous known-good production deployment;
5. a verified preview of the `web/` application;
6. rollback ownership and smoke-test steps.

The reviewed cutover may either remove the `git.deploymentEnabled` override or replace it with a narrowly scoped branch policy. A green Vercel badge alone is not cutover evidence.
