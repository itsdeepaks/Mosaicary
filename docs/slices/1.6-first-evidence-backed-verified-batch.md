# Product Plan v2 — Slice 1.6 First Evidence-Backed Verified Batch

Status: **PARTIAL — repository ingestion ready; human evidence gate BLOCKED**

## Goal

Promote a small, genuinely human-operator-reviewed set of Profiled Tessli sources only when their completed `tessli.resource-verification.v1` records satisfy every schema and semantic gate.

## Completed repository support

- added deterministic discovery for committed verification records under `web/data/resource-verifications/`;
- added a one-to-three-record batch checker that rejects malformed JSON, schema failures, unknown resources, stale fingerprints, duplicate resource IDs, incomplete or ineligible decisions, and secret-bearing fields;
- removed the `SourceProfile` dependency from the verification workflow so SourceProfiles can consume eligible records without a dependency cycle;
- made SourceProfile coverage, public JSON/Markdown, Source Detail, For AI, and MCP consume the same canonical derived coverage/date state;
- preserved the repository baseline with no committed verification records: `255 Listed / 40 Profiled / 0 Verified`;
- retained `verify_resource.liveCheckPerformed: false` and its repository-recorded-only boundary.

## Human gate

No provider has been promoted in this slice. A human operator must complete current official-source checks for the selected small batch, using the Slice 1.5 workflow, before a record is copied into `web/data/resource-verifications/`.

Required before promotion:

1. current availability observation;
2. every copied evidence claim confirmed;
3. every documented agent interface reviewed without storing credentials;
4. persistence, redistribution, attribution, and terms confirmed;
5. limitations reviewed, current freshness, valid recheck date, and non-empty decision notes;
6. `npm run verification:check -- <record>` and `npm run verification:batch-check` pass.

## Exclusions

- no provider network call, browser automation, or credential use;
- no record, source profile, catalogue row, coverage number, or source status promotion;
- no auth, cloud, homepage, playbook, media, or schema redesign;
- no claim that repository research is live-provider verification.

## Next action

Place only independently reviewed, completed eligible records in the committed directory, then run the focused batch/profile/MCP/public-representation checks and browser-review the affected source pages at the standard widths before considering this slice complete.
