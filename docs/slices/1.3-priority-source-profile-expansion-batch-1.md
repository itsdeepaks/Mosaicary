## Acceptance criteria

- exactly ten previously Listed sources gain complete intelligence profiles;
- every profile satisfies `resource-intelligence-profile.schema.json`;
- all claims retain current official evidence URLs and the review date;
- stable source IDs, slugs, canonical URLs, catalogue membership, and Playbook order remain unchanged;
- the static intelligence registry exposes all ten profiles to website and MCP consumers;
- deterministic generation reproduces the ten committed profile files from one batch source;
- public source JSON and Markdown expose the same normalized profile truth;
- coverage becomes exactly `265 Listed / 30 Profiled / 0 Verified`;
- every new record remains Profiled because explicit human/operator verification is not recorded;
- source-profile review/freshness date advances to the batch review date without changing freshness windows;
- focused profile, generation, public-representation, and MCP parity tests pass;
- complete formatting, typecheck, lint, tests, catalogue drift, build, browser, and release gates pass;
- Slice 1.3 becomes DONE and Slice 1.4 becomes NEXT only after exact-head validation and complete-diff review.

## Exclusions

- no source becomes Verified;
- no human-review provenance is invented;
- no live provider availability check is represented as completed verification;
- no source ID, slug, canonical URL, catalogue row, Playbook membership, or ordering change;
- no provider content, screenshots, font files, animation files, icons, design files, or paid/private assets are copied;
- no remote API or MCP call occurs during normal generation, test, or build;
- no Browse redesign, Source Detail redesign, homepage work, Pattern Candidate work, auth, cloud, submission, moderation, analytics, email, or deployment change;
- no new dependency or schema expansion.

## Governance boundary

`status`, `verifiedAt`, and evidence inside an intelligence profile describe the repository profile record. Public `Verified` coverage still requires the later Slice 1.5 operator contract and explicit completed human review. All ten records must therefore remain publicly Profiled.

Provider assets and user-owned workspace content remain outside Tessli. Evidence links support claims; they do not authorize mirroring or redistribution.

## Rollback

Revert the batch source, generated profiles, registry/generator/test changes, and bounded authority updates. Stable catalogue and Playbook data are unchanged, and no external state requires rollback.
