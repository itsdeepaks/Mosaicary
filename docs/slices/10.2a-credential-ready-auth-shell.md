# Slice 10.2a — Credential-ready auth shell and unavailable state

## Goal

Add Tessli's account entry point and responsive authentication shell without pretending that password, email-code, or Google authentication is active before a cloud Supabase project and provider configuration exist.

## Acceptance criteria

- `/auth` renders through the non-throwing Supabase readiness contract;
- the page is marked `noindex, nofollow` while account activation is incomplete;
- desktop and mobile headers expose a distinct Sign in entry point;
- the page uses Tessli's warm editorial visual system rather than a generic SaaS auth card;
- the shell explains the value of future accounts while confirming that public browsing and browser-local saves remain available without an account;
- configured and unconfigured readiness states use truthful status copy;
- Google, email, password, and six-digit code affordances are present only as disabled previews;
- no form submits, Supabase auth method, callback exchange, session refresh, proxy, or cookie mutation is introduced;
- keyboard, reduced-motion, forced-colours, mobile reflow, and focus behaviour remain supported;
- static contract tests, route smoke checks, responsive browser evidence, formatting, types, lint, all tests, catalogue drift, and production build pass.

## Exclusions

- no `signInWithPassword`, `signUp`, `signInWithOtp`, `verifyOtp`, `signInWithOAuth`, `exchangeCodeForSession`, or `signOut` call;
- no Google provider configuration;
- no custom SMTP or auth email template;
- no auth callback route, proxy/middleware, password reset, account menu, session UI, or protected route;
- no Supabase project, credential, schema, generated table type, migration, or RLS policy;
- no cloud saves, private collection writes, notes, or local-to-cloud import;
- no change to the public catalogue or future UI-intelligence track.

## State contract

### Unconfigured

- show `Account access unavailable`;
- explain that public project details are absent;
- keep all auth controls disabled;
- confirm that no sign-in request is sent;
- link back to public browsing.

### Configured but not activated

- show `Configuration detected`;
- explain that provider setup and live validation remain outstanding;
- keep all auth controls disabled until Slice 10.2b;
- do not infer a working backend merely from environment-variable presence.

## Pickup boundary

Slice 10.2b may activate password, six-digit email OTP, and Google only after Slice 10.1b supplies a real project and the required redirect, provider, SMTP, browser/server smoke, security-advisor, and rollback evidence.
