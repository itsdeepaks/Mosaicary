# Slice 5.3c — Reviewed media discovery pilot

Status: **active on `codex/reviewed-media-discovery-pilot`**  
Base commit: `cd3d47cf8fc8502e618e86340cc2baa5c1533481`

## Goal

Run the explicit 5.3b discovery workflow for exactly three asset-library resources, review every result manually, and publish only media records that satisfy Tessli's approved-media contract.

Pilot resources:

- unDraw — `resource-73d75733406d`
- Storyset — `resource-92baaed92865`
- DrawKit — `resource-08a9f0e0bd50`

## Acceptance criteria

1. Discovery runs only for the three listed resource IDs with an explicit checked date.
2. Network discovery output is captured as a temporary workflow artifact and is not committed as an `artifacts/` file.
3. Every redirect, source-page response, candidate URL, content type, failure, blocked result, SVG-only result, or uncertainty is preserved truthfully.
4. No image binary is downloaded or committed.
5. No authentication, anti-bot protection, paywall, or private content is bypassed.
6. Candidate records remain separate from approved production records until manual review is complete.
7. Each discovered preview and favicon is manually inspected for provenance, final response type, visual suitability, and obvious advertising/stale-campaign risk.
8. At most three records are approved for production; unsuitable or unresolved candidates remain review records and are not published.
9. Any production record added to `lib_data/resource-media.json` uses an existing resource ID, HTTPS credential-free public raster URLs, the verified content type, source page, source type, checked date, and reviewer evidence required by the approved schema.
10. The deterministic candidate reports and generated catalogue outputs are regenerated from repository sources.
11. Existing fallback order remains manual preview → Open Graph preview → favicon → generated letter mark.
12. Normal build, tests, catalogue generation, and CI remain network-free.
13. No UI, auth, Supabase, intelligence-profile, collection, pricing, access-model, or unrelated catalogue-content change is included.
14. Existing search, save/remove, media fallback, route, runtime-error, responsive, and overflow checks pass at 1440, 1024, 768, 390, and the repository's additional narrow-width gate.
15. The final PR contains no temporary discovery workflow or network artifact.
16. `build-slices.md` records 5.3c as `DONE` only after exact-head checks, visual review, and squash merge readiness.

## Exclusions

- no discovery for the remaining five queued resources;
- no mass enrichment of the 295-resource catalogue;
- no screenshot capture;
- no image proxy, first-party cache, wildcard image optimiser, or remote SVG;
- no automatic approval or publication;
- no invented URL, MIME type, licence, pricing, or access metadata;
- no third-party image binary;
- no changes to card layout or fallback implementation;
- no later refresh scheduler or broad-coverage slice.

## Planned workflow

1. Run explicit discovery for the three resource IDs and upload the JSON result as a short-lived workflow artifact.
2. Inspect the complete artifact and verify each public URL independently.
3. Update the committed candidate queue with truthful results and reviewer decisions.
4. Copy only approved records into `lib_data/resource-media.json`.
5. Regenerate deterministic reports and catalogue output.
6. Run focused tests, full repository checks, browser QA, complete-diff review, draft PR review, and squash merge.

## Rollback

Reverting this slice restores the 5.3b queue and the prior three approved production records. Discovery tooling and existing card rendering remain intact.
