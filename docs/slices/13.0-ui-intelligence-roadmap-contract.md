# Slice 13.0 — UI-Intelligence Roadmap Contract

Status: **documentation slice**  
Branch target: `docs/ui-intelligence-roadmap`

## Goal

Preserve the Landingfolio research and convert Tessli's future UI-intelligence direction into a repository-owned, implementation-ready roadmap without changing the current application, active product priority, catalogue data, authentication work, or deployment behaviour.

## Acceptance criteria

- [ ] A root roadmap explains the decision, architecture, non-goals, sequencing, gates, risks, measures, and pickup instructions.
- [ ] A dated Landingfolio study records observed product surfaces, official MCP claims, transferable patterns, rights risks, and a safe experiment plan.
- [ ] A provider-boundary contract classifies data, credentials, persistence, attribution, security, MCP, deletion, and provider-failure behaviour.
- [ ] A versioned JSON Schema defines a resource intelligence profile separately from the Phase 1 catalogue schema.
- [ ] The new schema parses as valid JSON and as a Draft 2020-12 JSON Schema.
- [ ] The profile schema can validate a representative Landingfolio profile.
- [ ] All factual external claims are attributed to dated official public sources and marked time-sensitive.
- [ ] The roadmap explicitly keeps this track deferred until active product work is complete or intentionally reprioritized.
- [ ] No runtime, UI, dependency, lockfile, catalogue, deployment, environment, authentication, or database file changes.
- [ ] The complete branch diff contains only the five documented files.
- [ ] Available repository CI passes on the exact pull-request head before merge.
- [ ] The PR is squash-merged and the branch is deleted.

1. parses `schemas/resource-intelligence-profile.schema.json`;

3. validates a representative Landingfolio profile;
4. rejects an invalid profile with an unknown persistence policy;
5. confirms all five expected files exist;
6. confirms Markdown files contain no embedded data-URI or committed screenshot payload.
