# Slice 7.2 — Full Reference responsive interaction

Status: **scoped**

## Goal

Replace Slice 7.1's smaller-screen Explore handoff with a complete Full
Reference experience for tablet and mobile while preserving the verified
desktop catalogue, shared discovery derivation, canonical URL state, and all
295 repository-managed resources.

## Acceptance criteria

- `/resources` retains the verified three-column desktop experience at the
  approved desktop breakpoint;
- tablet widths collapse both permanent sidebars and expose category and
  access filters through one labelled filter-sheet trigger;
- the tablet supporting panel becomes an inline factual disclosure rather
  than disappearing;
- mobile renders search first, followed by a filter/sort row and compact
  resource rows instead of the desktop table;
- compact rows expose factual resource name, domain, description, category,
  and access metadata progressively without hiding the external destination;
- every matching resource remains reachable without pagination, load more,
  virtualization, or infinite scroll;
- search, exact category filtering, multi-access OR filtering, and
  Curated/A–Z/Z–A sorting continue to use the existing shared discovery-state
  and result-derivation functions;
- `q`, `category`, `access`, and `sort` remain canonical and restorable through
  refresh, shared URLs, and browser back/forward navigation;
- opening the filter sheet reflects the currently applied URL state;
- applying filters closes the sheet, retains the invoking context, and
  announces the updated result count;
- cancelling or pressing Escape closes the sheet without applying draft
  changes and returns focus to the invoking control;
- focus is trapped inside the open sheet, background interaction is prevented,
  and the sheet remains usable with keyboard, touch, reduced motion, and
  forced-colours modes;
- filter and sort controls use native inputs/selects where practical, have
  visible labels and focus indicators, and provide approximately `44px`
  minimum touch targets;
- compact rows use native secure external links with
  `target="_blank"` and `rel="noopener noreferrer"`;
- result counts remain visible and politely announced;
- truthful empty and defensive data-error states work at tablet and mobile
  widths;
- no table or page-level horizontal scrolling is required for the primary
  tablet/mobile experience;
- no clipped focus indicators, hidden critical controls, invalid nested
  interaction, or essential hover-only information appears;
- browser behavior and screenshots pass at `1440×900`, `1280×800`,
  `1024×768`, `768×1024`, `430×932`, `390×844`, `360×800`, and `320px`;
- focused interaction tests, existing regressions, formatting, types, lint,
  catalogue drift, production build, route smoke, and CI pass;
- `build-slices.md` changes to `7.2 DONE / 8.1 NEXT` only after all verification
  and complete-diff review pass.

## Responsive interaction decisions

- `1100px` and above retains Slice 7.1's desktop table and permanent sidebars
  unless browser evidence requires a narrower, documented behavior threshold.
- `768–1099px` uses the catalogue list with a filter sheet and inline curation
  disclosure; it does not squeeze the three-column desktop frame.
- Below `768px`, the semantic table is replaced by compact resource rows. The
  mobile view is a recomposition, not a horizontally scrolling or visually
  hidden desktop table.
- Search stays directly available outside the sheet on tablet and mobile.
- Category and access choices are edited as a draft inside the sheet. Apply
  commits one canonical history entry; Cancel and Escape discard the draft.
- Sort remains directly available beside the filter trigger when it fits
  without crowding; otherwise it moves into the same sheet while remaining a
  labelled native select.
- The filter trigger communicates the number of active category/access
  constraints without inventing catalogue or usage facts.
- Resource descriptions and secondary metadata may use a native progressive
  disclosure on narrow screens, but the resource name, domain, external
  destination, category, and access model remain discoverable without hover.
- The factual curation disclosure reuses Slice 7.1 copy and links; no popular
  tags, rankings, quality scores, trends, or unsupported verification dates
  are introduced.

## Allowed visible copy

- existing Full Reference title, lede, facts, result labels, empty/error copy,
  curation disclosure, and contribution links from Slice 7.1;
- concise functional labels for Filters, Apply filters, Cancel, Clear filters,
  Sort resources, Show details, and Hide details;
- calculated result and active-filter counts derived from current local state.

Any new editorial or product claim requires source-backed repository evidence.

## Expected files

- `docs/slices/7.2-full-reference-responsive.md`;
- `web/components/full-reference/full-reference-experience.tsx`;
- `web/components/full-reference/full-reference.module.css`;

- `.github/workflows/web-ci.yml` responsive interaction and screenshot
  coverage;
- `build-slices.md` only after final verification.

An additional focused component file may be introduced only if separating the
sheet or compact row materially improves accessibility and testability without
creating a competing discovery-state implementation.

## Exclusions

- no save action, local storage, legacy-key migration, or Saved-page work;
- no authentication, Supabase, cloud data, or account UI;
- no resource detail route;
- no catalogue, validation output, schema, source CSV, category, collection,
  tag, media, or metadata changes;
- no remote metadata fetching, favicon scraping, preview-image scraping, image
  proxy, or external media request;
- no popularity, trending, rating, quality-score, usage, or save-count signal;
- no pagination, load more, virtualization, or infinite scroll;
- no redesign of the verified desktop Full Reference;
- no Explore, Collections, header, footer, or legal-content redesign;
- no new dependency or lockfile change;
- no analytics, tracking, production cutover, or deployment-policy change;
- no unrelated refactor or research-track work.

## Visual-reference decision boundary

`design.md` identifies
`design/reference/full-reference-desktop.webp` as canonical, but that path is
absent from merged `main`. The repository contains a tracked
`brand-preview/assets/full-reference-desktop.webp`, while the untracked
`docs/ref-img/full-reference-desktop.webp` belongs to the existing user
worktree and has a different SHA-256.

The tracked brand-preview image may be used to understand the already-approved
desktop composition, but implementation must not silently declare either
alternate file to be the canonical responsive reference. Before visual
implementation begins, resolve the documented path or explicitly approve the
responsive contracts and the verified Slice 7.1 desktop output as the Slice
7.2 visual baseline.
