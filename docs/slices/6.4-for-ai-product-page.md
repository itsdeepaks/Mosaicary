# Product Plan v2 — Phase 6 / Slice 6.4

Status: **DONE**

## Goal

Deliver a working `/for-ai` product page that explains how language models can use Tessli with or without MCP, documents the seven existing read-only native tools from shared repository truth, exposes the approved machine-readable and Board-export paths, and states coverage, confidence, freshness, privacy, and governance boundaries without overstating current capability.

## Page and route decisions

- `/for-ai` is a public, static, indexable product route;
- `For AI` becomes primary navigation only in the same slice that makes the route work;
- the page serves both people configuring an MCP client and people giving Tessli pages or exports to a model without MCP;
- the website and MCP server must consume one shared tool catalogue for tool names, titles, descriptions, and limits;
- setup guidance documents the existing local stdio server and Node.js requirement; it does not imply a hosted or remote MCP service;
- machine-readable examples link to real source-profile and Playbook JSON/Markdown routes;
- Board research packs remain browser-local copy/download output and are never represented as public server data;
- source coverage is derived from the canonical SourceProfile summary rather than typed marketing numbers;
- confidence and freshness explanations match the executable source-profile contract;
- the page distinguishes repository-recorded evidence from live provider verification;
- the page does not claim that retrieval alone gives a model design taste.

## Acceptance criteria

- `/for-ai` has metadata, one semantic `main`, one `h1`, logical headings, and useful server-rendered content;
- the page explains a complete without-MCP path using source pages, public JSON/Markdown, Playbooks, and browser-local Board research packs;
- the page explains the local stdio MCP path with Node.js 22+, repository setup, `npm run mcp`, and a bounded client configuration example;
- all seven existing tools are presented from shared metadata in canonical order:
  - `search_resources`;
  - `get_resource_profile`;
  - `compare_resources`;
  - `get_collection`;
  - `build_research_plan`;
  - `create_reference_packet`;
  - `verify_resource`;
- tool documentation states read-only behavior, important input bounds, output purpose, and repository-only limitations;
- the MCP server continues to expose exactly the same seven tools and imports their names/descriptions from shared truth;
- coverage facts are derived from `getSourceContractSummary()` and remain truthful for all 295 sources;
- Listed, Profiled, and Verified definitions are clear, including the current zero-Verified boundary;
- confidence and freshness rules match `deriveEvidenceConfidence()` and `deriveFreshnessStatus()`;
- real source-profile and Playbook JSON/Markdown example links work;
- the Board workflow links to `/boards` and clearly states that local Board data is not uploaded or included in public representations;
- governance copy states no live website/provider verification, screenshot retrieval, project-code ingestion, account access, credential use, or write operation;
- the page distinguishes `create_reference_packet` from the richer browser-local `tessli.board-research-pack.v1` Board export;
- `For AI` appears in desktop/mobile primary navigation and an appropriate footer group;
- sitemap and route/release smoke checks include `/for-ai`;
- the page recomposes at 1440, 1024, 768, 390, and 320 pixels with no horizontal overflow;
- keyboard focus, code blocks, links, tables/lists, and mobile content remain accessible;
- focused contract/browser tests and all repository, build, Web CI, and release gates pass;
- the active ledger marks Slice 6.4 DONE without unblocking the human-dependent homepage or proof slices.

## Exclusions

- no hosted, HTTP, SSE, OAuth-protected, or remote MCP endpoint;
- no eighth MCP tool and no Pattern, project-private, or approved-precedent retrieval;
- no live provider calls, web search, screenshots, crawling, or current pricing/licence verification;
- no Board upload, server persistence, cloud sync, account, authentication, or collaboration work;
- no public API, analytics, telemetry, rate limiting, or new external service;
- no source-profile enrichment, coverage promotion, catalogue membership, Playbook, or media change;
- no homepage rebuild, Pattern Candidate, evaluation outcome, or UI-taste claim;
- no copy/persistence of paid or private source content;
- no dependency addition unless an existing platform capability is demonstrably insufficient.

## Security, privacy, and governance boundary

The page is documentation over repository-backed read-only functionality. It must not accept credentials, execute arbitrary commands, read local project files, upload browser-local Boards, send analytics, proxy providers, or imply that Tessli has revalidated a source at request time. Configuration examples use placeholders for local absolute paths and must not expose user-specific paths or secrets.
