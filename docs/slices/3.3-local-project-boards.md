# Slice 3.3 — Local project Boards and notes

Status: implementation in review

## Goal

Add a versioned browser-local project workspace for creating and managing Boards, recording project goals and constraints, adding catalogue sources, and keeping per-source research notes.

## Acceptance criteria

- `/boards` is a working internal route;
- users can create, rename, switch, and delete Boards;
- each Board stores a project goal and constraints;
- users can add and remove any catalogue source;
- each Board source supports a plain-text research note;
- Board state is versioned, validated on read, and private to browser local storage;
- malformed local data degrades to an empty workspace;
- same-document and cross-tab changes are observed;
- Saved links to Boards and the sitemap includes `/boards`;
- keyboard, focus, labels, touch targets, responsive layout, and polite announcements remain usable;
- focused tests and full repository gates pass.

## Exclusions

- no selected/rejected state or rationale;
- no unresolved-question model;
- no Markdown export;
- no authentication, cloud sync, sharing, collaboration, or rich text;
- no catalogue, source-profile, Supabase, dependency, provider, or deployment-state change.

## Persistence contract

Key: `tessli-project-boards-v1`

Each Board contains stable ID, name, goal, constraints, timestamps, and source items with source ID and plain-text note. Unknown or malformed records are ignored rather than repaired with invented data.

## Rollback

Remove the `/boards` route, project-board components, test, sitemap entry, and Saved link. Existing local-storage data may remain inert in the browser and can be deleted safely by the user.
