## Configuration decision

The connected Vercel tool exposed project and deployment inspection but not project-settings mutation. The reviewed repository-level deployment contract therefore targets the nested `web/package.json` directly through `@vercel/next`. This avoids duplicating the Next.js workspace at the repository root.

Vercel warns that a `builds` configuration supersedes dashboard Build and Development Settings. That is intentional for this repository structure and is covered by the deployment-policy tests. The current package engine range also permits Vercel to select a newer compatible Node major; build and release gates must continue to validate the actual runtime selected by Vercel.

## Security boundary

This slice changed deployment routing only. It added no authentication, Server Action, upload path, database access, or user-data processing. The previously recorded transitive PostCSS/Sharp audit findings are not represented as fixed by this cutover, and no unsupported forced dependency override was introduced.
